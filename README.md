# Fieldnotes

Личный тренажёр английского B2. Next.js 16 + TypeScript, Supabase Auth/Postgres/private Storage, ts-fsrs. Интерфейс на русском, свои учебные тексты на английском. Самостоятельный репозиторий приложения enlab (интерфейс Fieldnotes).

## Запуск

Требуется Node.js 22.13+ (проверено на 24).

```sh
cd enlab
npm ci
cp .env.example .env.local
npm run dev
```

Открыть http://localhost:3000. Без переменных доступен только честно обозначенный гостевой просмотр пустого интерфейса. Демонстрационных учебных данных и локального сохранения учебных записей нет. Supabase SDK хранит сессию авторизации в браузере; сами данные находятся в PostgreSQL и Storage.

## Подключение Supabase

1. Создать проект на https://supabase.com/dashboard .
2. Открыть SQL Editor и выполнить целиком `supabase/migrations/001_initial.sql` один раз. Миграция создаёт таблицы, транзакционные функции, индексы, RLS и приватный bucket `originals` (10 МБ, PDF/TXT).
3. В Settings → API взять Project URL и publishable key (либо legacy anon key). Записать их в `.env.local` как `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Это публичные ключи с доступом только в рамках RLS. **service_role/secret key приложению не нужен.**
4. В Authentication → Providers включить Email/password. В URL Configuration указать Site URL: адрес размещённого приложения (для разработки http://localhost:3000). При включённом подтверждении email настройте SMTP для надёжной доставки писем.
5. Перезапустить dev server или пересобрать production. Нажать «Добавить выражение», зарегистрироваться, подтвердить письмо и войти. На телефоне открыть тот же сайт и войти в тот же аккаунт.

Политики ограничивают записи по `auth.uid()`, файлы по первой папке пути с UUID владельца. Составные внешние ключи не позволяют привязать запись к чужому материалу/выражению. Карточки и история меняются через RPC, история сохраняется при удалении выражения. Сохранение ответа блокирует строку карточки, проверяет версию, записывает историю и расписание одной транзакцией. UUID запроса предотвращает повтор ответа, включая повтор после сетевой ошибки. Расписание рассчитывается маршрутом `/api/review` с ts-fsrs. RPC доступен владельцу данных: это личный тренажёр, не система защиты результатов экзамена от самого владельца.

## Размещение

В Vercel импортировать репозиторий, **Root Directory = .**, Framework = Next.js, Node 24. Добавить две переменные из `.env.example` в Production и при необходимости Preview. Build: `npm run build`, Install: `npm ci`. После установки переменных выполнить Deploy. Обновить Site URL в Supabase на HTTPS-домен. Проект предназначен для размещения на Vercel из этого репозитория. Supabase подключается отдельно; без переменных окружения доступны учебная библиотека и гостевые тесты.

На собственном Node-хостинге: `npm ci && npm run build`, затем `npm start`, за HTTPS reverse proxy. Долгоживущий worker/cron для первой версии не требуется.

## Материалы и ограничения

- Оригинал загружается напрямую в закрытый Supabase Storage, без лимита тела запроса Vercel. До 10 МБ, PDF до 200 страниц, TXT UTF-8 до примерно 2 млн символов.
- PDF.js работает в браузерном Web Worker. Текст сохраняется по страницам, TXT по фрагментам около 3500 символов. После каждой страницы сохраняется checkpoint. При закрытии вкладки обработка останавливается; кнопка «Продолжить обработку» скачивает приватный оригинал и продолжает. Повтор страницы безопасен благодаря unique/upsert. Это возобновляемая обработка, не обещание фоновой работы после закрытия сайта.
- Пустой PDF/скан получает ошибку, а не ready. OCR, зашифрованные PDF, восстановление сложной верстки, таблиц и колонок не поддерживаются. На отдельных пустых страницах готового смешанного PDF показывается отсутствие текста.
- Позиция сохраняется при переходе между фрагментами; точный пиксель прокрутки не сохраняется. На телефоне можно ввести выражение вручную, контекст подставится автоматически.
- Интернет обязателен. Ошибки сохранения не закрывают форму и не засчитывают ответ. При возвращении в окно, восстановлении сети и входе данные обновляются с сервера. Синхронизация не использует realtime push. При конфликте версии карточки завершите занятие и начните снова с актуальным расписанием.
- Занятие содержит до 20 карточек из зафиксированной очереди, один ответ на карточку за занятие. «Не вспомнил» назначает ближайшее повторение FSRS для следующего занятия.
- Воспроизведение создаётся только при точном совпадении выражения с границами слов (без учёта регистра). Склонения и перефразирования не угадываются.
- Статистика использует часовой пояс текущего устройства. Для одинаковых границ дней установите одинаковый часовой пояс на Mac и телефоне.
- JSON содержит все учебные записи, фрагменты и полную историю, но не бинарные оригиналы. Их можно открыть отдельно в читалке через короткоживущую подписанную ссылку. Импорт архива пока не реализован.
- Нет offline cache/service worker. API и страницы имеют `Cache-Control: private, no-store`. Есть манифест и PNG-иконки для домашнего экрана.
- AI не подключён. Отдельные domain, material processing и review API позволяют позже добавить предложения AI до обычного сохранения выражения.
- Это первая версия для личной библиотеки: таблицы загружаются постранично, но целиком в память клиента. Для большой библиотеки потребуется серверная агрегация/поиск. Восстановление пароля через UI и удаление аккаунта пока отсутствуют; доступны средства Supabase Dashboard.

## Проверки

```sh
npm test
npm run typecheck
npm run build
# В другом терминале npm start
npx playwright install chromium
node scripts/verify-browser.mjs
```

Автоматизированные тесты запускают **настоящий SQL миграции** в PGlite (PostgreSQL WASM), эмулируя только окружение auth/storage. Проверяются: две роли пользователей, недоступность чужих карточек/выражений/истории, запрет прямой записи истории, идемпотентность, конфликт версии, сохранение истории при удалении. Отдельно проверяются FSRS, сериализация расписания, границы слов cloze, часовые пояса и CSV injection/escaping.

Браузерная проверка: 1440px/390px, навигация, отсутствие горизонтального переполнения, явное неподключённое состояние, offline-индикатор, настоящий PDF.js Worker для текстового и пустого PDF. Скриншоты в игнорируемой папке `test-results`.

### Что необходимо проверить после подключения облака

1. Зарегистрировать аккаунт A, подтвердить email, войти.
2. Загрузить английский UTF-8 TXT и текстовый PDF; дождаться ready. Прервать PDF после нескольких страниц и продолжить. Загрузить скан и увидеть ошибку.
3. Открыть материал, перейти к другому фрагменту, создать выражение с контекстом. Проверить duplicate warning, редактирование, удаление с подтверждением.
4. Начать занятие, раскрыть ответ, оценить. Перезагрузить страницу: ответ, due и история сохранены. При отключённой сети ответ не засчитывается; после восстановления повторить сохранение.
5. Во второй независимой браузерной сессии войти как A: сверить библиотеку, позицию, словарь, статистику. Одновременный ответ на одну версию карточки должен быть отклонён.
6. Войти как B: библиотека и словарь пустые. Проверить запросы по UUID материалов A и скачивание пути A через Storage API: доступа нет. Подписанная ссылка действует 60 секунд и является временным разрешением для её получателя.
7. На телефоне проверить выбор файлов, ручной ввод выражения из читалки и добавление на домашний экран.
8. Скачать CSV/JSON, сверить историю с БД.

Эти облачные сценарии **не заявлены как выполненные** без URL/ключа проекта и двух реальных аккаунтов. Локальные тесты SQL не заменяют проверку Supabase Auth/Storage и RLS в размещённом проекте.

## Учебная библиотека и тесты

Добавлены пункты «Правила и лексика» и «Тесты»:

- 16 грамматических тем B2: времена, conditionals/wish, модальные глаголы, пассив, косвенная речь, relative clauses, gerund/infinitive, артикли, количество, сравнения, связки и словообразование. В каждой — объяснения на русском, примеры на английском, частая ошибка и мини-проверка. Это базовый справочник B2, а не исчерпывающая грамматика.
- 8 тематических блоков, 64 выражения. Кнопка «В словарь» подставляет значение, пример и источник в существующую форму; сохранение требует аккаунта.
- 2 Reading + 2 Listening, по 8 вопросов (32 суммарно): True/False/Not Given, multiple choice, matching heading и note completion. Это оригинальные учебные мини-тесты по типам IELTS, не официальные варианты и не полный экзамен. Короткий результат не переводится в IELTS band.
- Таймер носит рекомендательный характер. Есть подтверждение завершения с пропущенными ответами и предупреждение при уходе из незавершённой попытки. Черновик живёт только в текущей вкладке; при перезагрузке он теряется.
- После проверки доступны правильные ответы, объяснения и подтверждающие цитаты. Транскрипты Listening открываются только после отправки. GET API не отдаёт ключи и транскрипты; проверка проходит на сервере. Это учебный режим, не защищённая система проведения экзаменов.
- Listening — два готовых M4A-файла в `public/audio`, с синтезированным британским голосом Daniel (macOS). Они работают на сервере/телефоне без speechSynthesis и без платного API. Есть обычный плеер, перемотка, повтор, скорость и сообщение об ошибке аудио. Нужен интернет. Учебная озвучка не заменяет практику с живой речью и разными акцентами.

**Существующий Supabase:** выполните `supabase/migrations/002_practice.sql` после `001_initial.sql`. Она добавляет `practice_attempts`, RLS, индекс и запрет перезаписывать попытки. Идентификатор отправки стабилен при повторе сетевого запроса: повторное сохранение не создаёт вторую попытку. Полный JSON-экспорт теперь включает `practice_attempts`. Самостоятельно изменяемые владельцем учебные данные не считаются защищёнными экзаменационными результатами.

Без Supabase/входа библиотека и тесты доступны. Гостевой результат явно не сохраняется в облаке. При входе результаты сохраняются на сервере; последние 20 доступны в разделе тестов на обоих устройствах. При ошибке записи показывается вычисленный результат с отметкой «не сохранён» и кнопкой повтора; ложного подтверждения нет. Старые попытки хранят полный снимок разбора и остаются понятными после изменения банка заданий.

Авторинг: `lib/course/grammar.ts`, `vocabulary.ts`, `tests.ts`. После изменения транскриптов на Mac запустите `npx tsx scripts/generate-audio.ts`, затем сохраните полученные M4A вместе с кодом; хостингу macOS не нужен. При изменении вопроса/ключа повышайте `version` теста.

Дополнительная браузерная проверка: `node scripts/verify-practice.mjs` при запущенном `npm start`. Покрывает грамматику, поиск, лексику, полное прохождение Reading, выдачу объяснений, повторы, Listening/audio decode/play, отсутствие ключей до отправки, сетевую ошибку и мобильную ширину. SQL-тесты включают права доступа к попыткам и повтор одного ID. Проверка облачной истории в двух настоящих Supabase-сессиях остаётся необходимой после подключения проекта.
